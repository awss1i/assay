<h1 align="center">Как работает assay</h1>

<p align="center"><a href="how-it-works.md">English</a> · <a href="how-it-works.zh-CN.md">简体中文</a> · <a href="how-it-works.ja.md">日本語</a> · <a href="how-it-works.ko.md">한국어</a> · <b>Русский</b></p>

---

<p align="center">assay открывает вашу страницу в настоящем браузере, находит на ней все элементы
управления (control), использует каждый из них в заранее спланированном наборе проверок (check) и
сравнивает страницу до и после каждой проверки. assay не знает, для чего нужна ваша страница,
поэтому сообщает о проблеме, только когда страница противоречит сама себе (the page contradicts
itself). Например, страница выбрасывает ошибку, элемент управления реагирует на одно нажатие позже
или счётчик показывает 1, когда список пуст.</p>

<p align="center">Первая половина этой страницы описывает, как проходит запуск. Вторая половина
разбирает каждый вид проверки: что делает assay, о чём он сообщает и какое именно сообщение выводит,
а также когда он намеренно молчит и почему. Каждое правило (rule) здесь измерено на
<a href="../bench/README.md">бенчмарках</a>, и большинство исключений появились потому, что более
широкая версия правила помечала как проблемную рабочую страницу.</p>

## <a id="how-a-run-goes"></a>Как проходит запуск

### <a id="serving-the-page"></a>Раздача страницы

assay раздаёт папку через localhost, а не открывает файл напрямую, потому что страницы, открытые
через `file://`, не могут загружать модули JavaScript.

assay никогда не запускает сборку вашего проекта. `npm install` выполняет любые скрипты, которые
есть в ваших зависимостях, а assay предназначен для кода, который ещё никто не проверял. Если
указать assay на дерево исходного кода, он подскажет, что нужно запустить самостоятельно.

```console
$ assay ./my-vite-app
assay: index.html loads /src/main.jsx, which a browser can't run without a build step.
  Build it in your own shell, then check the output:
    npm install && npm run build && assay my-vite-app/dist
  assay won't run the build itself, because installing dependencies runs their setup scripts, and assay is for checking code nobody has read yet.
```

---

### <a id="waiting-for-the-page-to-load"></a>Ожидание загрузки страницы

Событие `load` срабатывает раньше, чем большинство фреймворков успевает что-либо отрисовать, поэтому
assay не опирается ни на него, ни на фиксированную задержку. assay ждёт, пока элементы управления на
странице не перестанут меняться.

Страница, на которой виден только спиннер, тоже неподвижна, поэтому неподвижность считается
готовностью, только когда на странице появилось что-то, с чем можно взаимодействовать. Иначе
страница, застрявшая на *Loading…* (загрузка), выглядела бы как готовая страница без элементов
управления.

---

### <a id="finding-the-controls"></a>Поиск элементов управления

assay составляет список всех кнопок, полей ввода, выпадающих списков, холстов и ссылок, которые
отрисовывает браузер. Для каждого из них assay записывает CSS-селектор, метку, доступен ли элемент,
его размер, а также форму или контейнер, к которому он относится.

assay читает отрисованную страницу, а не исходный HTML. Элемент управления, созданный из JavaScript,
учитывается, а элемент, скрытый с помощью `display: none`, `visibility: hidden`, `opacity: 0` или
нулевого размера, не учитывается.

assay также находит элементы управления, которые не обозначены никаким HTML-тегом.

| элемент управления | как assay его распознаёт |
|---|---|
| ячейка сетки из обычных div | `cursor: pointer` |
| сортируемый заголовок таблицы | `cursor: pointer` на `th` |
| редактируемая область | `contenteditable` |
| ручка перетаскивания или полоса изменения размера | `col-resize`, `move`, `grab` или `draggable` |
| звезда или переключатель, нарисованные поверх скрытого поля выбора | видимый `label`, у которого радиокнопка или чекбокс скрыты |

Обработчики кликов, добавленные из JavaScript, нельзя прочитать со страницы, поэтому курсор мыши
часто остаётся единственным признаком того, что элемент что-то делает.

---

### <a id="planning-the-checks"></a>Планирование проверок

По найденным элементам управления assay составляет список проверок. Каждая проверка состоит из
одного или нескольких действий, например нажать кнопку дважды или заполнить форму и нажать кнопку,
которая её отправляет. Все виды проверок описаны во второй половине этой страницы.

Когда на странице много похожих элементов управления (одного вида, с одинаковой меткой и размером,
как ячейки сетки), assay использует не больше трёх из них, причём распределённых по всей группе, а
не первые три. До этого правила одна страница с сеткой из 256 ячеек получала план из 505 проверок, и
все лишние проверки сообщали одно и то же.

---

### <a id="running-each-check"></a>Выполнение каждой проверки

Каждая проверка выполняется в новой вкладке и начинается со страницы, которая только что
загрузилась. До и после проверки assay записывает:

- закрашенные пиксели каждого холста, их центр, их средний цвет и точный хеш пикселей,
- видимый текст,
- содержимое каждого поля ввода и то, отмечен ли каждый чекбокс,
- количество элементов на странице,
- хеш стилей и классов каждого элемента.

Холсты WebGL assay читает внутри кадра анимации, потому что к моменту, когда их мог бы прочитать
кто-то другой, их содержимое уже очищено.

`alert` считается откликом страницы. Окно с текстом *Length must be mm:ss* (длина должна быть в
формате mm:ss) означает, что форма правильно отклоняет неверный ввод, даже если больше ничего на
странице не изменилось. `prompt` или `confirm` означает, что страница задаёт вопрос, поэтому сам по
себе откликом не считается. Откликом считается то, что страница делает с ответом. assay отвечает на
prompt разумным значением и принимает confirm, а не отклоняет его, потому что отказ отменил бы ту
функцию, которую проверяют.

---

### <a id="passed-failed-or-not-checked"></a>Пройдена, не пройдена или не проверена

Проверка не пройдена (failed), когда нарушено одно из правил ниже. Иначе она пройдена (passed).
Проверка, которую вообще не удалось выполнить, отмечается как *not checked* (не проверена) и никогда
не считается проваленной.

Например, один сгенерированный калькулятор определяет собственную функцию `eval`, и из-за этого
ломается способ, которым assay читает страницу. assay сообщает следующее.

```
assay couldn't read this page, because the page replaces a built-in function that assay relies on (such as `eval` or `Function`). That doesn't mean the page is broken
```

Эта страница отмечается как не проверенная, а калькулятор на самом деле работает.

Бывает, что страница не даёт выполнить одно действие проверки. Например, по холсту, скрытому за
оверлеем *Press Space to start* (нажмите Space, чтобы начать), нельзя кликнуть. Тогда остальные
действия проверки всё равно выполняются. По этой причине проверка проваливается, только когда не
удалось выполнить ни одного её действия, и тогда сообщение начинается с *couldn't* (не удалось).

Отключённым элементом управления страница говорит «не сейчас». assay записывает, что элемент был
отключён, и не ставит его молчание в вину странице. Поле количества, которое вместо 25 подставляет
свой максимум 10 и отключает `+`, работает как задумано.

---

### <a id="grouping-findings"></a>Группировка замечаний

Когда из-за одного бага не проходят несколько проверок, первая неудача показывает сообщение, а
остальные ссылаются на неё.

```
C003 [FAILED] click blue twice
    → clicking this twice switched it back off, but the rest of the page didn't change back, so what the first click did is still in effect
C005 [FAILED] click green twice
    ↳ same finding as C003
```

Итоговая строка при этом сообщает, сколько из них повторы.

```
18 cases planned, 18 carried out, 10 passed, 8 failed (7 of them repeat an earlier finding)
```

Каждая неудача по-прежнему выводится и учитывается, а код завершения не меняется. Группировка меняет
только то, как читается вывод.

Две неудачи группируются, только когда выполняются оба условия:

- Они нарушили одно и то же правило с одним и тем же сообщением, не считая имён, которые в нём
  цитируются.
- Они произошли на элементах управления одного вида в одном месте, например на чипах одной панели
  тегов или на ячейках одной сетки. У элементов управления с именами, например у кнопок, имя тоже
  должно совпадать, поэтому Undo и Redo никогда не группируются.

Сбои группируются, только если у них одинаковое сообщение об ошибке и они были выброшены из одной и
той же строки кода.

Если все проверки выполнялись на странице, которая уже выбросила ошибку при загрузке, то замечание
(finding) обо всей странице, например о том, что ничего не реагирует, сообщает и об этом.

```
    ↳ the page threw an error while loading (C001), before anything was pressed
```

Каждая группировка на страницах бенчмарка сверяется с составленным вручную эталоном (answer key) в
файле [`bench/links.txt`](../bench/links.txt).

## <a id="what-assay-checks"></a>Что проверяет assay

Каждый раздел ниже сначала описывает, что assay делает со страницей, затем о чём он сообщает и,
наконец, когда он молчит и почему. Замечания об одной проверке нумеруются `C001`, `C002` и так
далее. Замечания обо всём запуске, которые не могла бы показать ни одна отдельная проверка,
нумеруются `F001`, `F002`, а два замечания обо всей странице (ничего не реагирует, ничего не
нарисовано) имеют номер `C000`.

### <a id="opening-the-page"></a>Открытие страницы

Первая проверка открывает страницу и ждёт, пока она успокоится, ничего не нажимая.

Если страница выбрасывает неперехваченную ошибку при загрузке или во время любой последующей
проверки, assay сообщает о ней и приводит сообщение об ошибке самого браузера.

```
C001 [FAILED] open the page and let it settle
    → the page threw an error and stopped running, Cannot read properties of null (reading 'addEventListener')
```

Каждая проверка, которая столкнулась с той же ошибкой, сообщает о ней, а повторы группируются под
первой.

Если страница вообще ничего не показывает, assay сообщает следующее.

```
    → the page shows nothing at all (no text, no images and nothing drawn), so there's nothing to test
```

Это правило появилось из-за React-приложения, компонент которого возвращал `null`. У приложения не
было элементов управления, поэтому единственной проверкой было «open the page» (открыть страницу), и
она прошла. assay сообщает о пустой странице, только когда на ней нечем пользоваться или когда
проверка, которая ждёт отклика (например, отправка формы), оставляет её пустой. Об инструменте для
рисования, который остаётся пустым холстом, пока вы на нём не нарисуете, assay не сообщает только
из-за того, что он пуст после загрузки.

---

### <a id="pressing-buttons-and-links"></a>Нажатие кнопок и ссылок

assay нажимает каждую кнопку и ссылку один раз, а затем дважды подряд, потому что баги состояния
часто проявляются при втором нажатии. Например, так бывает со вторым Start, с Undo после Undo или с
переключателем, который переключается только в одну сторону. Ещё assay нажимает первые три кнопки
парами в обоих порядках (Undo, затем Clear, и Clear, затем Undo), потому что страница может
правильно обработать один порядок и ошибиться в другом.

В этих проверках assay сообщает только об ошибках, которые выбросила страница. assay не требует,
чтобы кнопка что-то меняла, потому что не может знать, для чего она нужна. Образец цвета, который
задаёт цвет кисти и не показывает выделения, не меняет ничего видимого, и при этом он не сломан.
Когда более ранняя версия требовала видимого изменения, она помечала как проблемные 9 из 21 проверки
рабочего графического редактора. Что произошло, по-прежнему записывается в свидетельства (evidence),
например «the visible text is unchanged» (видимый текст не изменился), просто не как неудача.

Кнопку, которая никогда ничего не делает, assay всё равно находит двумя способами: когда у неё есть
противоположная кнопка, которая работает (см.
[противоположные пары](#buttons-that-come-in-opposite-pairs)), и когда на всей странице ничего не
реагирует (см. [страница, на которой ничего не реагирует](#a-page-where-nothing-responds)).

---

### <a id="typing-into-fields"></a>Ввод текста в поля

assay вводит в каждое текстовое поле четыре вида значений: пустое значение, обычный текст
(`Sample item`), строку из 300 символов и текст с запятыми, кавычками и HTML. В числовые поля assay
вводит пустое значение и число. В поля даты и времени (`date`, `time`, `datetime-local`, `month` и
`week`) assay вводит пустое значение и допустимое значение их типа. После ввода assay уходит из
поля, поэтому страницы, которые реагируют на событие `change`, его получают.

В этих проверках assay сообщает только об ошибках, которые выбросила страница. В поля только для
чтения assay никогда ничего не вводит, потому что это поля вывода. Например, генератор паролей
записывает свой результат в такое поле.

---

### <a id="filling-in-a-form-and-submitting-it"></a>Заполнение и отправка формы

Для каждого поля, после которого в той же форме или контейнере есть кнопка, assay заполняет все поля
этой формы, а затем нажимает кнопку. Перед нажатием assay также выбирает первый вариант в каждой
группе радиокнопок формы и меняет значение каждого выпадающего списка, потому что форма, которая
требует оценку или группу, правильно отказывается отправляться без них.

Каждое поле получает значение, которое принимает его тип: адрес электронной почты в поле email,
номер телефона в поле `tel`, URL в поле `url`, допустимую дату в поле даты. Только после этого assay
учитывает метку, поэтому текстовое поле с меткой *Phone* (телефон) получает `555-0100`, а поле с
плейсхолдером *mm:ss* получает `3:30`.

Это единственный вид проверки, в котором assay требует, чтобы что-то изменилось. Если в поле ввели
текст и нажали кнопку отправки, а на странице нигде ничего не изменилось, значит, страница ввод не
приняла.

```
C007 [FAILED] type into Title, then press Add
    → nothing on the page changed at all
```

assay не сообщает об этом в следующих случаях:

- **Кнопка не относится к полю.** assay нажимает только первую кнопку после поля в той же форме или
  контейнере. Кнопки фильтров в списке задач (All, Active, Done) правильно игнорируют введённый
  текст, а когда assay связывал поле с ними, он пометил как проблемные три рабочих списка. Для поля
  без кнопки после него, например в списке задач, который добавляет пункт по Enter, assay вообще не
  делает проверку отправки.
- **Поле является настройкой на странице с холстом.** На странице с холстом числовое поле или поле
  даты обычно задаёт настройку, например размер кисти, поэтому от страницы не требуется отклика, а
  судят о ней проверки холста.
- **Страница ответила окном alert,** например форма отклонила неверный ввод.
- **Кнопка отключена.**
- **Страница остановилась сама,** как закончившаяся игра, если только страница не сказала, что
  нажать (см. [игры](#games-and-animated-canvases)).

### <a id="adding-items-to-a-list-and-removing-them"></a>Добавление пунктов в список и их удаление

Список задач после загрузки состоит только из поля и кнопки. Чекбокс, кнопка Delete рядом с каждым
пунктом и счётчик оставшихся пунктов появляются только вместе с самим пунктом. Поэтому, когда на
странице есть форма, assay заполняет и отправляет её дважды, во второй раз с другими значениями, а
затем планирует проверки для каждого появившегося элемента управления. Каждая из этих проверок
начинается с добавления тех же двух пунктов, поэтому её название заканчивается на *with two saved*
(с двумя сохранёнными пунктами). Два разных пункта нужны потому, что Delete, который удаляет не тот
пункт, не может этого показать, когда пункт только один.

Если проверка удаляет пункт, но пункт, на котором нажали кнопку, всё ещё на месте, assay сообщает
следующее.

```
C014 [FAILED] press Remove, with two saved
    → this removed a row, but not the one it belongs to, and 'Another item https://example.com/other' is still there
```

Пункты с одинаковым текстом assay пропускает, потому что по ним нельзя понять, какой из них исчез.

В конце запуска assay также проверяет, что введённое в форму появилось в пункте, который форма
создала. Если часть введённых значений отсутствует, assay сообщает следующее.

```
F001 [FAILED] values typed into a list show up in the new row
    → 'https://example.com/page' was typed in and accepted, but the new row in the list doesn't show it, first seen at C009
```

Этого assay требует только от списка, то есть от всего, у чего менялось количество во время запуска,
включая строки обычной таблицы. Проверка идёт при двух пунктах в списке, потому что при одном пункте
нарастающий итог равен введённой сумме, и строка, которая показывает итог, выглядела бы правильной.
assay не сообщает об этом в следующих случаях:

- **Форма не является списком.** Форма регистрации, которая пишет *Account created* (учётная запись
  создана) и не показывает ни email, ни пароль, работает правильно и обязана скрывать пароль.
- **Не появилось ни одно из введённых значений.** Если строка не показывает ничего из введённого,
  список показывает что-то совсем другое, и дело не в одном пропавшем поле.
- **Страница отклонила второй пункт.** Значение, которое страница не приняла, не считается
  потерянным.

### <a id="numbers-that-count-or-total-a-list"></a>Числа, которые считают или суммируют список

На протяжении всего запуска assay читает каждое число на странице вместе с количеством пунктов в
списке и в конце сравнивает их.

Число, которое растёт и уменьшается на единицу вместе со списком, считает его пункты, поэтому при
пустом списке оно должно быть равно нулю. Если это не так, assay сообщает следующее.

```
F002 [FAILED] the count of items matches the list
    → a number on this page goes up and down by one with the list, so it counts the list, but it shows 1 when the list is empty. It's +1 off at every size
```

Для этого нужны как минимум три измерения при двух или более размерах списка, и assay берёт только
целые числа, потому что дробное число означает измерение или денежную сумму, а не количество.
Отличие на постоянную величину само по себе не считается ошибкой. Корзина, которая добавляет
фиксированную стоимость доставки, меняется вместе с содержимым и верна при любом размере. assay
отмечает только счётчик, который не равен нулю при пустом списке.

Число, которое меняется при каждом добавлении пункта, следует за списком, поэтому оно должно
меняться и при удалении. Если при удалении оно не меняется ни разу, assay сообщает следующее.

```
F003 [FAILED] a total that follows the list also goes down
    → a number on this page changed every time the list grew (4 times) but never when it shrank (2 times), so it stops following the list when items are removed
```

Так выглядит трекер расходов, который забывает пересчитать итог при удалении строки. Денежные суммы
здесь допускаются, потому что нарастающий итог является самым частым числом, которое должно
следовать за списком. assay должен был увидеть, как список и растёт, и уменьшается, а число должно
было меняться при каждом добавлении без исключения, потому что число, которое меняется лишь иногда,
отслеживает что-то другое.

### <a id="saving-and-reloading"></a>Сохранение и перезагрузка

После добавления двух пунктов assay проверяет, записала ли страница их в собственное хранилище
`localStorage` или `sessionStorage`. Если записала, страница обещает, что в следующий раз они будут
на месте, поэтому assay снова добавляет два пункта, перезагружает страницу и проверяет, что они всё
ещё показаны. Если они пропали, assay сообщает следующее.

```
C021 [FAILED] save two, reload, and they're still there
    → 'Sample item' and 'Another item' were saved in browser storage by the page, but are gone after reloading it
```

assay проверяет это, только когда страница и сохранила значения, и показывала их до перезагрузки.
Страницу, которая ничего не сохраняет, assay так не проверяет.

---

### <a id="clicking-cells-chips-and-cards-twice"></a>Два клика по ячейкам, чипам и карточкам

По кликабельным элементам, которые не являются кнопками (ячейкам сетки, чипам тегов, карточкам,
звёздам), assay кликает один раз, затем дважды подряд, а также кликает по первому из них и сразу по
соседнему. При двух кликах подряд assay следит не только за остальной страницей, но и за самим
элементом, потому что управляют именно им.

Если элемент не изменился после первого клика, а после второго изменился, он реагирует на один клик
позже, и assay сообщает следующее.

```
C011 [FAILED] click Mon 9:00 twice
    → when clicked twice, this didn't change on the first click and did on the second, so it reacts one press late
```

Это правило выявило планировщик, у которого стиль забронированного времени был инвертирован. При
втором клике должен измениться сам элемент, а не только страница вокруг него. Клавиша экранной
клавиатуры никогда не меняет собственный вид (каждое нажатие печатает букву на поле в другом месте
страницы), и когда изменение поля принималось за изменение клавиши, каждая клавиша отмечалась как
запаздывающая.

Если элемент изменился после первого клика и вернулся назад после второго, а остальная страница
назад не вернулась, assay сообщает следующее.

```
C003 [FAILED] click blue twice
    → clicking this twice switched it back off, but the rest of the page didn't change back, so what the first click did is still in effect
```

Так выглядит фильтр по тегам, у которого тег снова выглядит выключенным, а список остаётся
отфильтрованным. assay сообщает об этом, только если второй клик не изменил ничего, кроме самого
элемента. Папка в дереве, которая при закрытии закрывает и вложенные папки, при втором клике
перерисовывает дочерние элементы и количество строк. Так страница намеренно приводит дерево в
аккуратный вид, поэтому assay об этом не сообщает. Об элементе, который выглядит одинаково после
обоих кликов, например о миниатюре, которая открывает лайтбокс, assay тоже не сообщает.

В остальном эти клики assay оценивает так же, как нажатия кнопок, и сообщает только об ошибках.

---

### <a id="buttons-that-come-in-opposite-pairs"></a>Кнопки, которые образуют противоположные пары

Одиночной кнопке разрешено не делать ничего видимого. А вот две кнопки, которые отменяют действие
друг друга, страница объяснить не может, если одна из них меняет страницу каждый раз, а другая
никогда.

assay находит пары по меткам. Пару образуют две метки, которые отличаются ровно одним словом, если
это слово является противоположностью (next и previous, forward и back, undo и redo, up и down,
increase и decrease, more и less, plus и minus, add и remove или delete, expand и collapse). Кроме
того, assay нажимает кнопки парами в обоих порядках, поэтому молчащая кнопка нажимается сразу после
своей пары, когда ей есть что отменять. Если одна кнопка меняла страницу каждый раз, а другая ни
разу, assay сообщает следующее.

```
F001 [FAILED] Previous works as well as Next
    → Next changed the page, but Previous never did, even right after Next. As a pair, Previous should reverse what Next does
```

Previous в только что загруженной колоде слайдов правильно ничего не делает, поэтому assay учитывает
нажатие сразу после Next.

---

### <a id="drawing-on-a-canvas"></a>Рисование на холсте

С каждым холстом assay делает следующее:

- кликает по нему в четырёх точках, выбранных так, чтобы не попадать на границы ячеек при
  распространённых размерах сетки,
- использует его так, как обычно управляют подобной программой, то есть два клика, затем Space,
  стрелки вправо и вниз, Enter и перетаскивание,
- рисует на нём линию, а затем ещё одну линию в другом месте.

Если первая линия появилась, а вторая нет, холст перестал принимать рисование, и assay сообщает
следующее.

```
C019 [FAILED] draw on canvas, then draw somewhere else on it
    → the first line drawn on this canvas appeared, but a second line drawn elsewhere did not, so the canvas stopped accepting drawing
```

Перед тем как сообщить об этом, assay пробует провести вторую линию в нескольких местах. Холст,
который проигнорировал первую линию, эту проверку не получает вовсе. График ничего не рисует, когда
по нему перетаскивают курсор, и сам исключает себя тем, что не реагирует. Это правило выявило
графический редактор, который рисует одну линию и молча игнорирует все следующие, а ни одна другая
проверка плана этого не видела.

assay требует, чтобы клики по холсту меняли его, только когда на странице больше нечем пользоваться.
График рисуется по нажатию Add, а холст с прыгающими мячами пуст, пока вы не добавите мяч, поэтому
требование отклика от самого холста пометило как проблемные четыре рабочие страницы. Если страница
состоит только из холста и использование холста его не меняет, assay сообщает следующее.

```
    → the canvas this check clicked didn't change, even if other parts of the page did
```

Если холст и после этого ничего не показывает, assay сообщает следующее.

```
    → 1 canvas still shows nothing after every step of this check
```

Если в конце запуска ни один холст ни разу не показал ничего, кроме одного сплошного цвета, assay
сообщает об этом для всей страницы.

```
C000 [FAILED] something appears on the canvas
    → nothing ever appeared on this canvas. 12 checks used the page, and the canvas stayed one flat colour through all of them, so whatever the program draws isn't reaching the screen
```

Это правило выявило три куба на WebGL, у которых преобразование отсекало все вершины. По измерениям
холст был полностью закрашен одним цветом, и на нём ничего не было. assay сообщает об этом, только
если страницу использовали как минимум две проверки, ни одна другая проверка не провалилась и assay
добрался до каждого элемента управления на странице, потому что элемент, до которого он не добрался,
может оказаться тем, который запускает рисование.

---

### <a id="pressing-a-button-after-drawing"></a>Нажатие кнопки после рисования

Для каждой кнопки на странице с холстом assay рисует две линии, а затем нажимает кнопку дважды. Оба
нажатия начинаются из состояния, которое assay измерил, поэтому если первое нажатие ничего не
сделало, а второе что-то сделало, кнопка отстаёт на одно нажатие.

```
C016 [FAILED] draw on canvas twice, then press Undo twice
    → when pressed twice from the same starting point, this changed nothing on the first press and changed the page on the second, so it reacts one press late
```

Так выглядит история отмены, которая сохраняет состояние после каждого изменения, а не до него.
Первый Undo восстанавливает картинку, которая уже на экране. Нужны две линии, потому что с одной
линией в истории оба нажатия ничего не делают и дефект не виден. Проверка идёт после рисования, а не
на только что загруженной странице, потому что элемент управления, которому не на что действовать,
правильно бездействует.

Если вторая линия ничего не нарисовала, проверка вместо этого проходит, а в её свидетельствах
написано следующее.

```
the second line drew nothing, so there was no second step to undo
```

Правильный Undo тратит первое нажатие на этот пустой шаг, и это не отставание. Именно так рабочий
графический редактор, у которого не нарисовался второй штрих, раньше получал отметку о запаздывающем
Undo. Если вторая линия не нарисовалась, assay всё равно сообщает о самом холсте (см.
[рисование на холсте](#drawing-on-a-canvas)).

---

### <a id="games-and-animated-canvases"></a>Игры и анимированные холсты

Если холст анимируется сам, например в игре, которая идёт сама по себе, assay ждёт, пока он
остановится, и только потом действует. Если холст так и не останавливается, изменения на нём нельзя
приписать действиям assay, поэтому такие проверки не требуют изменений.

Если программа остановилась сама, например змейка врезалась в стену, assay не сообщает о том, что
она игнорирует последующие нажатия. Так игра и должна работать. Исключением является страница,
которая говорит, что нажать. Если она показывает *Press Space to restart* (нажмите Space, чтобы
начать заново), а нажатие Space ничего не меняет, страница нарушила собственную инструкцию, и assay
сообщает следующее.

```
    → the page says to press Space, but pressing Space changes nothing
```

Закончившаяся игра без возможности перезапуска всё равно может выглядеть сломанной, и это указано в
ограничениях в README.

---

### <a id="dragging-handles-and-rows"></a>Перетаскивание ручек и строк

Разделитель панелей и строка, которую можно переставлять перетаскиванием, ничего не делают при
клике, поэтому assay их перетаскивает:

- Каждую ручку перетаскивания (курсор `col-resize`, `move` или `grab`) assay перетаскивает, а во
  второй проверке перетаскивает дважды. Во второй проверке assay измеряет только второе
  перетаскивание, потому что чаще всего разделитель ломается так, что сдвигается один раз, а потом
  его уже не ухватить, и если измерять оба перетаскивания вместе, первое скрывает второе.
- Каждую строку с атрибутом `draggable` assay перетаскивает в дальний конец её списка с помощью
  настоящих событий перетаскивания HTML5. Именно в дальний конец, потому что большинство списков
  вставляют строку перед целью. Строка, брошенная на соседнюю, возвращается на своё место, и такой
  список выглядел так, будто перетаскивать в нём нельзя.

От перетаскивания assay ожидает, что оно изменит страницу. Если этого не происходит, assay сообщает
следующее.

```
C012 [FAILED] drag the divider, then drag it again
    → nothing on the page changed at all
```

### <a id="sliders-checkboxes-dropdowns-colours-and-files"></a>Слайдеры, чекбоксы, выпадающие списки, цвета и файлы

assay сдвигает каждый слайдер до упора, отмечает каждый чекбокс и радиокнопку, выбирает другой
вариант в каждом выпадающем списке, задаёт каждому полю выбора цвета другой цвет и передаёт каждому
полю выбора файла небольшой файл того типа, который оно принимает.

В этих проверках assay сообщает только об ошибках, которые выбросила страница, по той же причине,
что и для кнопок. assay не может знать, что должен менять слайдер или чекбокс. Эти действия всё
равно считаются использованием страницы, которое нужно проверке
[ничего не реагирует](#a-page-where-nothing-responds).

### <a id="tabs-and-expandable-sections"></a>Вкладки и раскрывающиеся разделы

Во время каждой проверки assay читает каждую вкладку и каждый заголовок раздела на экране. Элемент
управления с `aria-selected="true"` или `aria-expanded="true"` сообщает программам чтения с экрана,
что панель, указанная в его `aria-controls`, показана. Если эта панель вообще не отрисована,
страница противоречит сама себе, и assay сообщает следующее.

```
F001 [FAILED] the panel a selected tab or open section controls is shown
    → "Tab 2" is marked selected and controls the panel "panel-1", but that panel isn't shown, first seen at C004
```

Пустая панель всё равно считается показанной, потому что у неё есть блок на странице. assay отмечает
только панель, которую браузер не отрисовывает совсем.

---

### <a id="labels-and-radio-buttons-in-the-markup"></a>Метки и радиокнопки в разметке

Во время каждой проверки assay также читает, как связаны метки и радиокнопки, и сообщает о трёх
ошибках, которые нельзя увидеть, глядя на страницу:

- Две радиокнопки в одной группе с одинаковым значением, из-за чего форма не может понять, какая из
  них выбрана.

  ```
  F002 [FAILED] labels and radio buttons are linked correctly
      → two radio buttons in the "option" group both have the value "2", so the form can't tell which of them was picked, first seen at C001
  ```

- Метка, у которой `for` указывает на несуществующий id.

  ```
      → the label "Email" is linked to "emial", but nothing on the page has that id, first seen at C001
  ```

- Две метки, связанные с одним элементом управления, из-за чего элемент, для которого
  предназначалась вторая метка, остаётся без метки.

  ```
      → two labels are both linked to "star4", so one of them was meant for another control, which is left without a label, first seen at C001
  ```

### <a id="fields-whose-placeholder-fails-their-own-pattern"></a>Поля, чей плейсхолдер не проходит их собственный шаблон

assay читает каждое поле, у которого есть и `pattern`, и плейсхолдер. Если собственный пример поля
не проходит собственный шаблон поля, человек, который введёт значение как в примере, не сможет
отправить форму, которая требует это поле.

```
F001 [FAILED] the zip box accepts its own placeholder example
    → the placeholder shows "12345" as an example, but the pattern on this field, \d{5}, rejects it, so someone who types what the example shows can't submit a form that requires this field
```

assay находит эту ошибку по разметке, а не через ввод, потому что поле, из-за которого появилось это
правило, находится на одном из дальних шагов мастера, до которого проверки не доходят. Плейсхолдер с
пробелом assay не трогает, потому что это инструкция вроде *Enter five digits* (введите пять цифр),
а не пример значения.

### <a id="nan-undefined-and-object-object-on-the-page"></a>NaN, undefined и [object Object] на странице

Во время каждой проверки assay ищет `NaN`, `undefined` и `[object Object]` в видимом тексте и в
каждом поле. Ни одна страница не показывает их намеренно. Они означают, что значение использовали до
того, как его задали, или вычислили из чего-то, что не является числом. assay сообщает следующее.

```
F001 [FAILED] no NaN, undefined or [object Object] on the page
    → the page shows `NaN` where a value should be, "Total: NaN". This usually means a value was used before it was set, or calculated from something that isn't a number, first seen at C008
```

assay не сообщает об этом из проверки, в которой он сам ввёл что-то, что не является числом.
Конвертер температур, получивший `Sample item`, правильно показывает `NaN`, потому что это верный
ответ на заданный ему вопрос. Пустое поле здесь считается числом.

---

### <a id="a-page-where-nothing-responds"></a>Страница, на которой ничего не реагирует

Отдельные проверки не требуют, чтобы кнопка что-то делала, и страница, все кнопки которой ни к чему
не подключены, прошла бы каждую из них. Поэтому в конце запуска assay задаёт этот вопрос про всю
страницу. Если элементы управления использовались, а на странице так ничего и не изменилось, assay
сообщает следующее.

```
C000 [FAILED] something on the page responds when used
    → nothing on the page changed after any control was used. 14 checks used what the page offers and none of them changed it, so the controls don't seem to be connected to any code
```

Это правило выявило канбан-доску, у которой три кнопки Add ни к чему не были подключены. Такое
замечание объявляет сломанной всю страницу, поэтому assay сообщает о нём, только если выполнены все
условия:

- использовались как минимум два разных элемента управления,
- ни одна проверка не увидела никаких изменений где-либо на странице,
- assay добрался до каждого элемента управления на странице. Однажды assay так отметил сортируемую
  таблицу, у которой он использовал кликабельные ячейки, но не добрался до заголовков сортировки, а
  сортировала она безупречно.
- страница всё так же ничего не делает, когда её открывают заново и дают ей несколько секунд вместо
  доли секунды, и так трижды. Страница, у которой Retry запускает двухсекундную загрузку, выглядит
  бездействующей за то время, которое даёт одна проверка.

## <a id="what-assay-cant-check"></a>Что assay не может проверить

assay не знает, что должен делать элемент управления, поэтому страница, которая работает, но делает
не то, например итог, который неправильно складывает, обычно проходит проверку. Чтобы проверить, что
должен делать элемент управления, напишите критерии приёмки и передайте их из Python.
`check(folder, criteria=[...])` принимает сценарии с собственными действиями и ожидаемыми
результатами, и эти ожидания проверяются так, как они написаны.
